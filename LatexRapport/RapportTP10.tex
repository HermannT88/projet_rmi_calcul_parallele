import java.rmi.server.UnicastRemoteObject;
import java.rmi.RemoteException;
import java.rmi.registry.Registry;
import java.rmi.registry.LocateRegistry;
import java.rmi.server.ServerNotActiveException;

public class LancerService {
  public static void main(String args[]) throws RemoteException, ServerNotActiveException {
    try {
      Service nom = new Service(); // creation d un objet (new)
      ServiceInterface rd = (ServiceInterface) UnicastRemoteObject.exportObject(nom, 0); // 0 pour que OS donne le port automatiquement
      Registry reg = LocateRegistry.getRegistry(1099); // 1099 port par defaut des annuaire (modifiable)
      reg.rebind("LeNom", rd); // donner un nom dans l annuaire pour le service
    } catch (RemoteException e) {
      System.out.println(e.getMessage());
    }
  }
}

\textbf{Le/les processus fixes (ceux qui écoutent sur un port choisi) et les processus mobiles ? (ceux qui rentrent et sortent a leur guise)?}

Les processus mobiles sont représentés par les différents nœuds de calculs qui peuvent s’enregistrer et se déconnecter. On peut également considérer le client qui est à l'origine de la demande de calcul comme un processus mobile.

Le processus fixe est le service qui va transmettre le calcul aux différents noeuds de calculs. Le service et enregistré sur un port 


\textbf{Les types des données échangées entre les processus}

Le client envoie un fichier .txt et les coordonnées relatives à la création de l'image (deux pour le point intial et  deux pour la longueur et la largeur des pixels). Il reçoit un objet "Image" une fois celle-ci construite.

Le service central reçoit un fichier .txt. il envoie des calculs qui permettent de définir le pixel aux différents noeuds.

Une fois ces calculs réalisés, les noeuds retourne le résultat et le service central va l'interpréter.



\textbf{Si on veux que les calculs se fassent en parallèle que faut-il faire ?}
